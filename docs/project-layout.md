# Project layout

A project keeps everything Helix Loop needs in one hidden folder, `.helix/`, at its root.
Commands find it the way git finds a repository: the nearest folder up from where you are.

```
my-product/
  .helix/
    config.yaml          the project's configuration (configuration.md)
    spec/
      spec.md            the Helix Spec (or one Markdown file with the spec's own name)
      sections/          generated by `helix-loop spec index`: one file per section
      index.json         generated: section keys and requirement IDs
      clarifications.md  answers sent from the app, waiting to be folded into the spec
    plan/
      taskset.yaml       the TaskSet: its revision, timelines, and Lane › Epic › Feature › Story
      milestones.yaml    Helix Milestones: the delivery order, as demoable outcomes
      tasks/T-####.yaml  one file per builder task, naming its story
      human/HT-##.yaml   one file per human task
      history/
        index.yaml       each revision of the TaskSet: when, who, why, and what it added
        r<N>/            a superseded revision, kept whole: taskset.yaml, milestones.yaml, tasks/, human/
      synthetic-reqs.yaml  requirements the spec states only in prose
      deferred-reqs.yaml   requirements left for later on purpose
      ImplementationPlan.md, HumanImplementationPlan.md, DependencyMap.html
                         generated by `helix-loop plan render`; never edited by hand
    prompts/
      build.md           the prompt every pass starts from, with the task and its spec sections filled in
    helix/
      rules.yaml         what your ratings taught Helix
      prompts/*.local.md your edits to Helix's prompts
    app.yaml             this machine's app settings: folds, filters, the last visit to Home (not committed)
    runs/                the loop's ledger, logs, metrics and state (not committed)
    repos/               the product repositories the loop builds (not committed: each has its own remote)
    worktrees/           one git worktree per running pass (not committed)
    .gitignore           keeps the last four out of git
```

## What to commit

Commit `config.yaml`, `spec/`, `plan/` (its `history/` too), `prompts/` and `helix/` with the project: they are its source, and the loop commits its own plan updates (a task merged, a task waiting on you) into the same repository.
`.helix/.gitignore` keeps the rest out.

## Where the tool's own files are

The schemas the plan is checked against, Helix's preset prompts, the templates `init` copies, the Helix skill and the app itself ship with Helix Loop, not with each project.
`helix-loop skill` says where the skill is installed.
