1Loop control room: the jobs, then four home directions and one pass at every other screen
What Daniel does when managing a loop
Grouped by job and ranked by how often each happens. Every screen below is built so the top rows take one click from home.
1 · Unblock the loop (many times a day)
Do a human task, ordered by what it holds up · mark it done with evidence · copy its handoff prompt · answer a builder's spec question · hand back a needs-human task with a note
2 · Act on the monitor's fixes (daily)
Accept, edit or decline a proposed fix: retry with a note, park, split, add a dependency, quarantine a flaky test · dismiss as noise
3 · Check it's moving (all day, at a glance)
Running or stopped · what each agent is on · finish date and how far it moved · throughput · anything stuck too long
4 · Steer the plan (weekly)
Reprioritise a branch · add or cut a dependency · split a task that grew · edit notes · ask the Helix to make a plan change
5 · Watch or step into a pass
Watch an agent live · read the gate result · stop a runaway pass · send its feedback to the monitor
6 · Run, release, stay healthy
Start, stop, dry run · approve and tag a release · sign in or install an agent · check quota and pace
How builder feedback reaches Daniel
Two agents, one inbox. The Health monitor watches the loop; the Helix answers Daniel and changes the plan.
